# 安全门禁与异常处理

以下检查必须早于爆品判定、覆盖天数、优先级和采购公式。硬门禁失败的 SKU 只能进入异常清单。

## 认证与账号

硬拦截：

- Connector Skill 未加载或版本不明确
- 商家密钥缺失、Token 失败、Session 校验失败
- 只读接口未返回 `code=200` 与 `data.success=true`
- 密钥与目标商家账号不匹配

不得打印或保存到 Skill：完整 `appSecret`、Token、Session、签名串。

## 销量口径

- `ALL_STATUS` 未经样本验证：允许生成“估算建议”，禁止采购写操作。
- 任一销售窗口失败或缺失：停止正式计算。
- `Q3=0、Q7>0`：先核对缺货、下架、活动结束、渠道缺数和映射变化；原因未知则硬拦截。
- 活动、直播、异常大单：标记活动驱动，输出试算并要求人工确认。
- 未支持平台贡献主要销量：停止全店建议；只允许明确标记覆盖范围的部分渠道分析。

## 商品资格

默认排除名称或标签包含：测试、勿动、赠品、虚拟、定金、补差价、运费、停用、删除、清仓。商家白名单可以覆盖关键词，但必须明确确认。

以下商品不进入采购明细：无供应商、不可采购、代发无需备货、ERP SKU 映射缺失、`sysSkuId` 不唯一。

## 库存与在途

硬拦截：

- 可配货库存小于 0
- 库存字段非数字或关键字段缺失
- 候选查询无法用 `sysSkuId` 唯一匹配
- 必需数据源分页或覆盖范围不完整
- 库存在途与采购单剩余在途冲突且未核对

未查到库存不能当作 0；负库存不能改成 0。两份在途不能相加。

在途 ETA 未知时可以输出静态试算，但 `write_eligible=false`。若到货晚于断货日，不应把该在途视为覆盖交期内风险。

## 业务参数

首次正式运行必须明确 L、R、S。交期缺失或只使用未经确认的全局默认值时，只输出试算。SKU 级交期优先于供应商级，供应商级优先于商家默认值。

## 写操作门禁

采购单创建需要全部满足：

1. 用户已经看过最终明细。
2. 用户明确回复“确认创建采购单”。
3. 建议有唯一 `recommendationId`、快照时间和有效期。
4. 确认前重新查询库存和在途；关键数据无变化。
5. 每个 SKU 的 `write_eligible=true`。
6. 有可靠的重复创建防护和执行状态。
7. 仓库、供应商和费用与接口能力一致。

当前环境没有可靠幂等、多仓或供应商选择能力时，只生成采购单明细，禁止真正调用创建接口。

## 原始错误处理

API 返回不明确错误、total 与列表不一致、应有数据却为空或参数异常时：立即停止，原样展示服务端响应，建议检查权限或联系开放平台客服。禁止调整参数反复试探、自动全量翻页或写循环绕过限制。

## 建议有效期

默认建议有效期 60 分钟。超时、库存变化、在途变化或再次运行时生成新批次；旧批次标记过期，不得继续确认。
