# 解决方案边界与产品定义

## 目标

把销售趋势、可配货库存、采购在途和供应商交期统一到 `sysSkuId` 口径，回答：哪些商品正在成为爆品、哪些商品有断货风险、今天建议采购多少。

爆品识别与缺货风险必须分开：销量规模、增速、加速度和头部排名决定爆品；预测日销、库存位置和交期决定断货风险。库存为零不能直接定义为爆品。

## 双 Skill 职责

| 层级 | 职责 |
|---|---|
| `kdzs-sales-driven-replenishment` | 触发、流程编排、业务配置、规则计算、异常拦截、结果解释和写操作确认 |
| `kdzs-erp-api-connector` | 凭证、Token、Session、签名、接口参数、原始调用和服务端错误 |

解决方案 Skill 不复制连接器的签名和 API 实现；连接器升级后应重新加载并按新契约执行。

## 最小商家输入

首次使用必须确认：

- 供应商平均到货周期 `L`
- 复盘周期 `R`：每天为 1，每周为 7
- 爆品安全天数 `S`

日常触发可简化为：“帮我生成今天的爆品补货建议。”

## 适用范围

适合已经维护 ERP 货品映射、订单、库存和采购数据，且主要经营开放平台支持渠道的单仓或默认仓商家。建议版可用于人工采购决策；采购闭环需要额外满足幂等、供应商、仓库、权限和审计条件。

## 当前限制

- 不支持淘宝、天猫、1688、淘工厂和拼多多数据查询。
- 交期及在途 ETA 不是当前 API 的可靠自动字段。
- 库存和采购查询有分页上限，且连接器禁止擅自全量翻页。
- `ALL_STATUS` 的有效销量语义必须用商家真实样本校准。
- 创建采购单无法可靠完成多仓、多供应商选择和幂等保护。

因此默认产品定位为“只读建议版 MVP”。用户明确确认也只能在所有安全门禁满足时执行写操作。

## 分阶段落地

1. 建议版：读取四窗口、候选 SKU 库存和在途，输出可解释建议，不创建采购单。
2. 试点版：增加状态口径校准、商品资格过滤、交期配置、建议快照与有效期。
3. 闭环版：完成采购幂等、权限审计、供应商和仓库验证、创建后回查。

## 成功标准

- 每个建议都有原始窗口、公式和原因。
- 关键数据不完整时不生成正式采购量。
- 测试或不可采购商品不进入采购明细。
- 未经确认的采购单创建次数为 0。
- 同一建议不会重复创建采购单。
